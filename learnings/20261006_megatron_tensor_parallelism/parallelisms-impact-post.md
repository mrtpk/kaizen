I've been digging into how parallelism changes the way an LLM is served. Parallelism here means splitting the work across GPUs: data parallelism copies the whole model, tensor splits each layer, pipeline splits the layers into stages, and expert spreads the experts of a mixture-of-experts model. The catch: only data parallelism leaves latency alone, because the other three put inter-GPU communication on the path of every token. Let's say we serve a model on 4 GPUs: with data parallelism, each GPU runs its own copy, so we get up to 4× the throughput at the same latency, as long as the model fits on one GPU; with tensor parallelism, every layer has to wait for all 4 GPUs to sync before moving on. It means that "which parallelism is fastest?" has no single answer: it depends on whether you care about latency, throughput, or just fitting the model in memory. So, the next time someone says "just add more GPUs", ask them: for which goal? 🙂
